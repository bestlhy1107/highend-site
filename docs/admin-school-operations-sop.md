# 院校模块管理员日常 SOP

这份 SOP 面向实际在后台处理院校搜索、候选审核、底库补齐和周报复盘的管理员。

适用页面：

- `/admin/school-search`
- `/admin/study-abroad-catalog`

核心目标：

- 让用户搜索时尽量“搜得到”
- 让错误候选尽快被规避
- 让热门国家 / 专业的正式项目和门槛覆盖持续变厚

## 1. 每日开工清单

每天上班后，固定按这个顺序看：

1. 打开 `/admin/school-search`
2. 看 `全网扩搜状态`
3. 看 `本周一句话结论`
4. 看 `本周自动复盘建议`
5. 看 `下周自动执行清单`
6. 看 `最近搜索留痕`
7. 看 `待审核候选`

优先级判断规则：

- 先处理零结果搜索
- 再处理低结果搜索
- 再处理候选很多但明显不准的搜索
- 最后处理一般性补厚任务

## 2. 日常巡检标准

### 2.1 扩搜状态

在 `/admin/school-search` 确认：

- 全网扩搜状态已启用
- 没有提示“未配置百度扩搜密钥”
- 最近搜索留痕里候选官网页数量不是长期为 `0`

如果扩搜状态异常：

- 先执行部署文档里的运行时自检
- 参考 [deploy-aliyun.md](/Users/liuhuiyang/Desktop/桌面%20-%20Liuhuiyang’s%20MacBook%20Air/webindex/highend-site/docs/deploy-aliyun.md)

### 2.2 执行清单状态

在 `下周自动执行清单` 里确认：

- 有没有长期停留在 `待执行` 的计划
- 有没有长期停留在 `处理中` 但一直没有完成的计划
- 有没有最近完成的计划还在周报里反复出现

### 2.3 周报状态

在 `本周执行周报` 里确认：

- 本周有动作记录是否在增长
- 本周已完成计划是否为 `0`
- 当前仍待推进数量是否越来越大
- 最近最常执行的动作是否过于单一

## 3. 搜索异常处理 SOP

## 3.1 零结果搜索

入口：

- `零结果治理清单`

处理顺序：

1. 先判断是不是用户条件太窄
2. 如果是细分方向太窄，优先放宽方向
3. 如果正式库太薄，点 `先补这组门槛`
4. 如果已有同类候选，点 `查看同类候选`
5. 如果最近同类留痕很多，再点 `查看最近同类留痕`

完成标准：

- 该类搜索后续不再长期为 `0`

## 3.2 低结果搜索

入口：

- `低结果治理清单`

处理顺序：

1. 先点 `补厚这组正式项目`
2. 如果当前在重点国家推广期，点 `按国家推进这组`
3. 如果结果主要靠候选撑着，转去 `候选撑起搜索清单`

完成标准：

- 正式项目数提升
- 学校池数量提升
- 低结果样例数下降

## 3.3 候选很多但质量差

入口：

- `待审核候选`
- `候选撑起搜索清单`

处理顺序：

1. 先丢弃明显不相关单条
2. 对同域名多次重复出错的来源做整域规避
3. 对可能仍有价值的来源，先保留单域名，只丢弃单条
4. 对高可信官网候选，导入正式项目

完成标准：

- 同类查询里明显错误来源减少
- 候选转正式项目效率提升

## 4. 候选审核标准

### 4.1 可导入正式项目

满足以下多数条件时可导入：

- 来源是院校官网或高可信官方招生页
- 国家、学位、项目名称基本明确
- 页面不是资讯、问答、活动新闻
- 页面内容与用户搜索方向基本一致

### 4.2 应直接丢弃

以下情况优先丢弃：

- 聚合资讯站
- 留学软文站
- 纯问答页
- 宣讲活动页
- 无法确认具体学校和项目的页面

### 4.3 应整域规避

以下情况优先整域规避：

- 同一个域名多次在不相关搜索中出现
- 同一个域名反复被人工判定为低质量来源
- 不是目标院校官网，而是搬运、聚合、软文内容站

## 5. 门槛补齐 SOP

入口：

- `/admin/study-abroad-catalog`

### 5.1 日常维护

直接执行：

- `按推荐节奏立即执行`

### 5.2 国家重点期

如果近期重点推某个国家，执行：

- `按这个国家的推荐方向补齐`

### 5.3 单方向救火

如果某个方向结果明显不足，执行：

- `只补这个方向`

### 5.4 正确顺序

- 项目池太薄：先同步底库
- 项目池够了：再补门槛

## 6. 执行清单 SOP

入口：

- `下周自动执行清单`

使用规则：

1. 优先处理 `待执行`
2. 点真实动作后，系统会自动切到 `处理中`
3. 完成后手动标记 `已完成`
4. 每次推进后都看：
   - 最近执行动作
   - 最近动作时间
   - 完成时间

异常处理：

- 如果动作已执行，但状态没变，先刷新页面确认
- 如果多次执行仍无状态变化，记录时间和计划名称后交开发排查

## 7. 每周固定动作

每周至少做一次完整复盘：

1. 跑评测
2. 看趋势
3. 看榜单
4. 看执行清单完成情况
5. 看本周周报

命令：

```bash
cd /root/highend-site
set -a
source ./.env
set +a
npm run study-abroad:eval
```

关注指标：

- 通过率
- 零结果数
- 低结果数
- 候选主导数
- 平均正式项目数
- 平均学校池数

## 8. 每周 KPI 建议

建议跟踪这些指标：

- 本周零结果查询减少数
- 本周低结果查询减少数
- 本周导入正式项目数
- 本周门槛补齐完成组数
- 本周规避来源数
- 执行清单完成率

## 9. 异常升级规则

以下情况建议立即升级处理：

- 扩搜状态异常，连续无法返回候选结果
- 正式结果大面积突然下降
- 同一查询开始大量出现错误来源
- 执行动作报错且无法重试成功
- 周报连续两周显示关键指标变差

## 10. 管理员一句话工作标准

每天的目标不是“看了后台”，而是：

- 让用户今天更容易搜到结果
- 让错误候选今天就开始减少
- 让热门方向的正式结果和门槛今天更完整
