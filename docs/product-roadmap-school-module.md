# 院校模块产品排期版 Roadmap

这份 Roadmap 面向产品、开发、运营一起协作的排期视角，重点关注“先做什么最值、怎么验收、谁来推动”。

## 当前模块定位

院校模块当前已经具备三层能力：

- 用户搜索层
- 后台治理层
- 评测与执行层

下一阶段不建议重写，而是继续沿着这三层把体验、质量和运营闭环做深。

## 阶段 1：稳住线上扩搜与真实放量

时间建议：

- 1 周

目标：

- 让线上候选扩搜稳定放量
- 让后台能持续接住这些候选结果

交付项：

- 生产环境扩搜密钥稳定接通
- 最近搜索留痕能持续产生候选官网页
- 候选审核区能看到真实放量任务
- 错误来源开始进入规避链路

验收标准：

- 运行时自检通过
- 至少 3 组真实搜索能稳定产生候选官网页
- 后台 `/admin/school-search` 可看到对应留痕和待审核候选

负责人建议：

- 开发：部署、运行时校验、接口验收
- 运营：候选审核、错误来源清理

## 阶段 2：提升搜索质量与前排可信度

时间建议：

- 1 到 2 周

目标：

- 结果更多，但前排更准

交付项：

- 扩充评测样例到 30 到 50 条
- 热门国家 / 热门专业方向补齐样例
- 高频误命中来源加入规避名单
- 搜索推荐理由持续优化
- 结果偏少时的放宽建议更稳定

验收标准：

- 零结果率下降
- 低结果数下降
- 候选主导查询下降
- 高频错误来源反复出现的概率下降

负责人建议：

- 产品：确定重点国家和方向优先级
- 运营：维护真实搜索样例和规避清单
- 开发：排序、召回、治理逻辑迭代

## 阶段 3：把后台做成真正的运营工作台

时间建议：

- 2 周

目标：

- 后台从“分析面板”升级成“执行面板”

交付项：

- 执行清单完成率统计
- 已完成计划自动归档
- 周报增加平均处理时长
- 规避命中统计
- 候选审核备注和处理历史

验收标准：

- 管理员能清楚知道本周做了什么
- 管理员能追踪哪类任务总是卡住
- 周报可以支持周会复盘

负责人建议：

- 产品：定义周报字段和管理指标
- 开发：状态流、统计、归档
- 运营：按周复盘执行结果

## 阶段 4：做强用户侧转化能力

时间建议：

- 2 周

目标：

- 搜索结束后更容易导向咨询和跟进

交付项：

- 收藏学校和项目
- 保存搜索条件
- 搜索结果导出
- 一键生成咨询摘要
- 项目对比视图

验收标准：

- 用户能把搜索结果带走
- 用户和顾问之间的信息交接更完整
- 搜索后咨询转化率提升

负责人建议：

- 产品：定义用户操作链路和转化文案
- 设计 / 前端：结果页表达和交互增强
- 运营：顾问承接口径统一

## 阶段 5：Python 高价值切入

时间建议：

- 2 到 4 周

目标：

- 把最脏最重的搜索数据工作从前台逻辑中拆出去

优先切入项：

- 官网页面抓取
- PDF / HTML 门槛抽取
- 候选评分
- 学科归一化
- 离线搜索评测和批处理补库

不建议先动的内容：

- 前台站点整体重写
- 后台 CMS 重写
- 全量迁移到 Python

验收标准：

- Python 抽取质量稳定高于当前规则版
- 候选噪音下降
- 热门方向的门槛补齐速度提升

负责人建议：

- 产品：定义切入边界，不要一次动太多
- 开发：先做独立服务，不重写前台
- 运营：提供真实失败样例辅助调优

## 阶段 6：长期产品化能力

时间建议：

- 持续迭代

目标：

- 从搜索工具走向持续使用的留学产品

候选项：

- 收藏学校 / 项目
- 保存搜索条件
- 导出结果摘要
- 顾问工作台
- 热门查询自动补库
- 搜索失败自动告警
- 用户搜索历史
- 顾问一键生成推荐摘要

## 按优先级排序的后续待开发项

P0：

- 线上扩搜稳定性
- 评测集扩充
- 高频错误来源清理

P1：

- 执行清单统计与归档
- 周报完成率和处理时长
- 候选审核备注与处理历史

P2：

- 收藏学校和项目
- 保存搜索条件
- 搜索结果导出
- 一键生成咨询摘要
- 项目对比视图

P3：

- Python 抓取与抽取服务
- 更深的自动补库与评测系统

## 每阶段必须有的验收动作

每完成一个阶段，都建议固定做：

1. 跑搜索评测
2. 做 2 到 3 组真实线上搜索验收
3. 检查后台治理面板是否有新留痕
4. 确认动作按钮和状态流没有断
5. 记录一版阶段性结论

## 当前最值得推进的下一项

如果按投入产出比排序，当前最值得马上推进的是：

1. 收藏学校和项目
2. 保存搜索条件
3. 搜索结果导出
4. 一键生成咨询摘要
5. 项目对比视图

也就是优先把“用户搜完之后怎么带走结果、怎么进入咨询”补全，再继续做更重的 Python 数据层。
